# RepoShelf — decisions

One line per decision: `D-n decision — why — rejected alternative`. D-1..D-17 from ARCHITECTURE §0, D-18..D-31 from
the gap fixes in TASKS.md, D-32.. made while implementing.

- D-1 Clone hosts = any public `https://` host; `owner/repo` = github.com, `host.tld/owner/repo` = https; no credentials callback ever — public archive only, no secret handling — ssh/credential prompts, github-only.
- D-2 Managed clones are bare (`<archive>/<host>/<owner>/<name>.git`), never checked out — no Windows file-name/long-path failures, browsing reads objects anyway — non-bare clones with checkout.
- D-3 Fetch allowed for managed clones and imported repos with an https origin; writes only `refs/remotes/origin/*`, new free tags (via staging) and `FETCH_HEAD` — the single, bounded write exception to NFR-O2 — fetch for managed clones only / full `git fetch` semantics.
- D-4 Markdown rendered in Rust: comrak (GFM) → ammonia allow-list, one pipeline for READMEs, `.md`, tag notes, GH release bodies — one sanitiser on trusted side — DOMPurify/markdown-it in the webview.
- D-5 Syntax highlighting in TS: highlight.js core + lazy languages in a Web Worker, class tokens only — no inline styles so CSP needs no `unsafe-inline` — Shiki (inline styles, WASM), syntect (no TSX, CPU on command thread).
- D-6 Hand-written hash router (~200 lines) — needs are small and react-router 8 is unverified on this machine — react-router.
- D-7 Refs in routes are one percent-encoded segment, resolved with a fixed precedence (§3.5) — no ambiguous longest-prefix guessing — GitHub-style multi-segment refs.
- D-8 Line anchors in the route query (`?L=10-20`); "Copy link" shows GitHub form `#L10-L20` — hash is taken by the router — `#L` fragments inside a hash route.
- D-9 Commit paging = offset paging over one pinned tip (`tip` + `skip`) — restarting a time-sorted walk at a cursor drops interleaved merge-side commits — cursor-oid paging.
- D-10 Native dialogs and external links opened from Rust; webview has no dialog/opener/fs/shell permissions — smallest webview attack surface — plugin JS APIs in the webview.
- D-11 No asset protocol; images fetched as bytes over IPC and shown via `blob:` URLs — no fs scope to get wrong — `asset:` protocol with scopes.
- D-12 UI repo identity = slug `owner/name` (origin owner or `local`), numeric `repoId` over IPC, collisions `-2`, `-3` — readable URLs, ids never trusted as paths — paths or hashes in URLs.
- D-13 Default archive dir `Documents\RepoShelf`, data dir `%LOCALAPPDATA%\dev.schwi.reposhelf`, env `RS_DATA_DIR`/`RS_ARCHIVE_DIR` win — lead's decision, visible archive for the user — archive under the app id dir.
- D-14 File-clone test seam `clone_from_unchecked` only under `cfg(any(test, feature="testkit"))`, enabled in src-tauri only via non-default feature `e2e` (separate build); M9 checks `RS_TEST_FILE_CLONE` is absent from shipped exe — tests need local sources without weakening the shipped URL policy — runtime flag in the shipped app.
- D-15 `crates/rs-cli` dev tool (fixtures, bench, inspect), not shipped — PoC criterion 3 needs a bench — benches inside the app.
- D-16 Optional "uncommitted changes" note for imported non-bare repos, off by default, `statuses()` without `UPDATE_INDEX` — never write the index of imported repos — always-on status.
- D-17 No diff syntax highlighting in the PoC (plain lines coloured add/del) — scope — highlighted diffs.
- D-18 `ImportPreview` gets `token: String`; src-tauri keeps `token → (path, expiry 10 min)` — `import_confirm` needs a token the preview never carried — passing the path back from the UI.
- D-19 `RepoSummary` gets `cloned_at: Option<i64>` — FR-18 shows "Cloned <date>" — a separate detail call.
- D-20 `fetch::fetch` = URL policy + `fetch_from(source)`; `fetch_unchecked` under the testkit cfg; e2e build routes `file://` origins there with `RS_TEST_FILE_CLONE=1` — fetch tests and the e2e smoke need `file://` upstreams — relaxing the https rule.
- D-21 `testkit::register_raw(&Shelf, path, source) -> i64` inserts a `repos` row by SQL (M1) — M2 caches need a repos row before `library::import` exists (M3) — reordering milestones.
- D-22 `ghreleases.rs` implemented in M3 behind feature `ghreleases` (on in src-tauri), tested with canned JSON only — module had no milestone — dropping optional FR-31 notes.
- D-23 Extra testkit fixtures `big-tree` (50k), `huge-commit` (400 files), `corrupt`, `missing` — bench and NFR-O3/FR-4 had no inputs — ad-hoc fixtures in tests.
- D-24 IPC samples golden committed at `src/ipc/__samples__/ipc-samples.json`; Rust test compares (`UPDATE_SAMPLES=1` rewrites), vitest reads the golden — `npm test` must not depend on a prior `cargo test` — reading `target/ipc-samples.json`.
- D-25 e2e harness runs only `target\e2e\release\reposhelf.exe`, built with `npx tauri build --no-bundle --features e2e` and `CARGO_TARGET_DIR=target\e2e` — plain cargo build leaves the app on the dev URL — e2e against the portable exe.
- D-26 Shipped builds only via the tauri CLI / `-p reposhelf`, never `--workspace` release — feature unification would compile testkit into the app — workspace release builds.
- D-27 Search/filter/sort implemented once in TS (`filterRepos`, `sortRepos`); Rust `library::search` dropped — the list already lives in the TS store — two implementations.
- D-28 `Settings.recent` dropped; "Recent" = top 5 by `repos.last_opened_at` — duplicated state — a settings list.
- D-29 Measurement steps added: `rs fixtures --register 50` + e2e start-time (NFR-P1), light/dark screenshot pass (M8), NFR-W3 badge (M6.6), NFR-A1 (M5.10) — requirements had no step — leaving them unverified.
- D-30 Trash behind a `Trasher` trait (`RealTrash` = `trash::delete`, tests use a recording fake) — tests must not fill the real Recycle Bin — calling `trash` directly.
- D-31 Virtualised lists use `useWindowVirtualizer` (window scroll) — the router's `scrollY` restore must apply — inner scroll containers.
- D-32 IPC wire shape: unit-only enums serialise as camelCase strings (`"imported"`); enums with data are internally tagged `{"type": "<camelVariant>", …camelCase fields}` (unit variants `{"type":"ok"}`, newtype `Fetched(FetchOutcome)` flattens) — TS gets discriminated unions, `jobs.kind_json` uses the same shape — serde's default external tagging (mixed string/object shapes).
- D-33 `validate::clone_url` refuses URLs whose archive dir components (host dir, owner, folded name dir) fail `winpath::path_ok_here` (e.g. owner `aux`, `x.`); port and IPv6 hosts map to storable dirs (`host_8443`, `[::1]` → `__1`) — the bare clone must be creatable on Windows — failing later inside the clone job.
- D-34 `validate::git_path` drive-prefix rule is `X:` alone or followed by `/` or `\` (refuses `c:/x`, `C:\x`, `Z:`) — `a:b.txt` is a legal git file name that NFR-W3 requires to stay browsable; paths are never joined onto the filesystem — the literal `^[A-Za-z]:` rule.
- D-35 `JobCtx::progress` always emits on a phase change and on `Finalizing`, otherwise ≥ 80 ms apart; `JobRunner::retry` inserts the new row before deleting the old one — the UI must see every phase switch, and SQLite reuses the rowid of a deleted max row — pure time throttle / delete-then-insert.
- D-36 `commits::latest(s, repo_id, repo, rev)` takes the repo id — the commit-count cache is keyed `(repo_id, tip)` — ARCH §3.4's signature without it.
- D-37 Commit paging: `PageQuery.skip` counts walk positions (= commits when unfiltered) and the returned `CommitsPage.skip` is where the next page starts; a capped path-filtered scan ("Search older commits") continues from it — §6.4's "returned skip" made concrete; continuation always progresses — counting only matching commits (a capped scan would rescan from the tip forever).
- D-38 `rsrepo:` is not in ammonia's URL schemes: only our relative-URL rewrite (applied after ammonia's scheme check) emits it, so author-written `rsrepo:` links are dropped; `data:` passes the scheme check but an attribute filter keeps only `data:image/(png|gif|jpeg|webp)` in `img[src]`; fragment-only links get `#user-content-` (comrak `header_id_prefix_in_href`) — no author-controlled in-app URLs — `rsrepo` in the scheme allow-list.
- D-39 Git paths are resolved by walking tree entries segment by segment (`tree::lookup`, lossy-name fallback for non-UTF-8 names, R-7), never via `std::path::Path`, never joined onto a filesystem path — the guard D-34 relies on (`a:b.txt`, `CON.txt` browsable, `storable_here=false`) — `Tree::get_path(Path)`.
- D-40 Diff caps: > 300 files → file list only (no stats); ≤ 300 files but > 20k changed lines → stats + file list, no inline diffs (FR-28); otherwise inline hunks for files ≤ 2,000 changed lines; `binary` is taken from the loaded patch (libgit2 sets it only then) — FR-28 wording — ARCH §6.5's "inline while running total ≤ 20k" (partial inline diffs).
- D-41 Large fixtures (wide-dir, long-history, big-tree, huge-commit) are written through an in-memory ODB backend and stored as one packfile (`testkit::packed`); `corrupt` stays loose so one object file can be deleted — 50k loose files are slow to create and unrealistic to read — loose objects.
- D-42 rs-core dev-depends on itself with `features = ["testkit"]` so `tests/immutability.rs` runs under plain `cargo test -p rs-core` — the gate runs without features — `required-features` (silently skipped).
- D-43 Last-commit results that hit the 10k cap are cached like complete ones (older entries stay "older than 10,000 commits"); tags sort by tagger date for annotated tags, else commit date (ARCH §6.7/TASKS over FR-30's "target commit date"); the dirty note counts untracked files (ignored files and submodules excluded) — cheap second visits, one documented order — recomputing capped dirs on every visit.
- D-44 https→http redirect downgrade is refused by libgit2 itself (verified in vendored libgit2-sys 0.18.8+1.9.7: WinHTTP's own redirects are disabled via `WINHTTP_DISABLE_REDIRECTS`, `winhttp.c` applies a `Location` only when it starts with `https://` (otherwise replays the same https URL until "too many redirects"), and `net.c` `git_net_url_apply_redirect` rejects any scheme change whose target is not https, for every redirect policy); clone/fetch keep `RemoteRedirect::Initial`. The real bypass, git config `url.*.insteadOf` (repo or user-global), is enforced in code: the remote's effective URL must equal the validated URL, else `Refused` before connecting — offline proof without TLS certs is impossible; a config rewrite is the reachable downgrade — a transport/certificate callback (sees no final URL).
- D-45 libgit2 on Windows refuses a git dir whose path + 92 chars exceeds MAX_PATH and any loose ref/reflog path over MAX_PATH, whatever `core.longpaths` says: clone refuses an archive path that is too long before creating anything (readable `Refused`); refs whose loose file (`logs/<prefix><name>.lock`) would exceed MAX_PATH are skipped and reported like other unstorable refs (`clone::drop_long_refs`, clone and fetch); `\\?\` (`paths::long`) for every std::fs op. Only the local `file://` transport (tests) DWIM-looks-up every advertised name in the receiving repo (local.c `local_negotiate_fetch`), so there an overlong name fails the whole clone — asserted as such — `core.longpaths` alone (no effect on these checks).
- D-46 Network counter is per-thread (`clone::note_net_call` before every git2 connect/fetch and the GitHub GET; `testkit::net_calls()` reads it) — parallel clone tests would break a global "stays 0" assertion — a global atomic. `testkit::snapshot`/`snapshot_diff`/`read_everything` moved from tests/immutability.rs into testkit so M3.9 reuses them.
- D-47 Fetch uses an anonymous remote on the re-validated, rebuilt https URL with explicit refspecs (`prune` off, `AutotagOption::None`; nothing fetched when the refspec list is empty), so `remote.origin.*` config is never read for URL/refspecs nor written; staging refs are cleared by a drop guard; `new_commits` = one revwalk over changed remote-tracking tips hiding all previous remote-tracking tips and local branch tips (no double counting); `fetch_all` continues past failures and returns one `Refused` listing them — exactness and no config writes on imported repos — fetching through the named `origin` remote / Σ per-ref walks.
- D-48 Import slug = lenient parse of any origin form (https, ssh://, scp-like `git@host:o/r`) → `owner/name`, else `local/<folder>`; non-repo folders → `NotARepo` (not `RepoCorrupt`); picking `<repo>/.git` imports the work tree; duplicates compared on the canonical path (`COLLATE NOCASE`). The unchecked seam clones into `<archive>/file/<parent>/<name>.git`. `jobs::shelf_worker(Arc<Shelf>)` and (testkit-gated) `shelf_worker_unchecked` are the M4.1/M4.9 worker closures — imported repos commonly have ssh origins; one worker definition — `validate::clone_url` for slugs.
- D-49 ghreleases: ureq agent `https_only`, `max_redirects(0)`, 10 s, UA `RepoShelf`; raw API JSON cached (parsed first, bad JSON never replaces the cache), drafts dropped, bodies rendered through `markdown::render` at merge time; GitHub only overrides title/notes of existing tag cards (never adds cards); only `https://github.com/<o>/<r>` origins — no redirect to a foreign host — following redirects (renamed repos fail with an HTTP 301 message).
- D-50 `repo_remove` trashes a folder only when `source = cloned` AND its canonical path lies strictly inside the archive dir; the trash runs before the DB delete (entry kept if the Recycle Bin refuses) — `relocate` can point a "cloned" entry at any user folder — trusting `source` alone.
- D-51 Command layer: each command is `#[tauri::command] async fn` → `spawn_blocking(x_impl(&AppState, …))`, state managed as `Arc<AppState>`; dialogs, opener and trash behind `Picker`/`Opener`/`Trasher` traits; `path`/`rev`/`oid`/`requestId` are validated before the repo lookup (hostile input → `invalidPath`/`invalidRev` even for an unknown `repoId`) — command tests need no runtime, window, dialog or Recycle Bin — calling plugin APIs directly in commands.
- D-52 Job errors get the IPC wording: `state::friendly_worker` wraps the rs-core worker and re-wraps `Git`/`Network`/`Refused` errors as `Refused(friendly text)` (credentials / 404 / "Could not reach <host>" / plain insteadOf text; host from the job kind), `Cancelled` untouched — `JobRunner` stores `Error::to_string()`, so `IpcError` mapping alone never reaches the jobs popover; `FetchAll`'s combined message keeps rs-core's per-repo text — mapping inside rs-core.
- D-53 `jobs_subscribe` keeps one `Channel` per webview label (a reload re-subscribes and replaces it), registers before taking the snapshot, and drops channels whose send fails — sends into a reloaded page never fail, so an append-only list would grow per reload — keeping every channel ever subscribed.
- D-54 Capability = `core:event:default` only (narrower than ARCH §8's `core:event` + `core:app`): in tauri 2.12.5 app commands are not ACL-gated without an app manifest and `plugin:__TAURI_CHANNEL__|fetch` is exempt (`webview/mod.rs`); verified live (commands, Channel, event listen work; `plugin:window|set_title` is denied) — smallest webview surface — `core:default`.
- D-55 Window `main` is created in `lib.rs` (`tauri.conf.json` `windows: []`): `on_navigation` allows only `http(s)://tauri.localhost` and `tauri://localhost` (+ `http://localhost:1450` when `tauri::is_dev()`), `on_new_window` → Deny, `data_directory(<RS_DATA_DIR>/webview)` when `RS_DATA_DIR` is set; the opener plugin is built with `open_js_links_on_click(false)` (no injected click script). Verified live: `window.open` and `location.href = https://…` stay on the app — config windows cannot take the data dir — keeping the config window.
- D-56 Tauri 2.12.5 does not apply `devCsp` to the devUrl document (`tauri dev`: no CSP meta, an injected inline script ran), while the production `csp` is enforced in a `tauri build --no-bundle` exe (inline script blocked, `script-src-elem` violation). M4.14's "zero CSP errors" is therefore also checked on the built exe; M8's e2e on the built exe is the real CSP gate — a dev-only check would prove nothing.
- D-57 src-tauri features: `default = ["ghreleases"]` forwarding to rs-core (off → `releases_fetch_github` answers `unsupported`), `e2e = ["rs-core/testkit"]`; rs-core with `testkit` is a dev-dependency only (tests); `rs_core::types::samples` is public under the testkit cfg and seeds the IPC golden (keys `Type` or `Type.variant`) — one sample list — duplicating samples in src-tauri.
- D-58 IPC shapes beyond ARCH §5.1: `repo_locate` → `RepoSummary | null` (dialog cancelled), `repo_remove` → `RemoveResult { trashed }`, `blob_save_as` checks the blob before opening the dialog; `blob_bytes` returns raw bytes only, the image MIME comes from `blob_meta` (`BlobKind.image.mime`); `branches_ahead_behind` compares with HEAD's branch; a `request_cancel` that arrives before its request registers is remembered 30 s; event `library-refreshed` (payload `RepoSummary[]`) after the startup refresh; `open_external` stays http/https only (no `mailto:`) — UI needs found while writing the commands — ARCH table as written.
- D-59 happy-dom upgraded to `^21` (21.0.4) at the start of M5 (lead's decision; `npm audit` → 0 vulnerabilities, all 95 earlier TS tests green) — fixes the audit finding — staying on 20.x.
- D-60 One command table `src/ipc/commands.ts` (`Commands`: snake_case name → camelCase args + result) types `bridge.call` and the mock's handler table (`{ [K in CommandName]: … }`), and `COMMAND_NAMES_COMPLETE` checks the 47-name list at compile time — a missing or drifted command fails `npm run typecheck` in api and mock alike — hand-typed mock functions.
- D-61 The mock backend is reached only through `import('./mock')` in `bridge.ts` when `__TAURI_INTERNALS__` is absent: its own chunk (≈ 54 KB), not in the initial JS; it ships in `dist` (invented fixture data only) but is unreachable in the app — a build-time alias that would need two builds.
- D-62 Highlighter: an explicit `LOADERS: Record<LangId, () => import(…)>` map (48 languages, one chunk each; a template `import()` would not split). hljs 11 has no continuation API, so files > 2,000 lines get the first 2,000 lines highlighted alone (fast first paint) and then one full pass posted in 2,000-line chunks that replace it; worker body in `hl/engine.ts` so it is unit-tested; worker via `new Worker(new URL('./hl.worker.ts', import.meta.url), { type: 'module' })` (`worker-src 'self'`) — chunk-by-chunk highlighting (wrong state at chunk borders) / blob workers.
- D-63 Tokens are literal hex per theme; the dark global header has its own tokens (`--header-bg/-fg/-fg-muted/-input-bg/-border`) and the accent is deep teal (`#1b6a80` light / `#4fbfc8` dark) with an indigo focus ring; `contrast.test.ts` reads `tokens.css` from disk (vitest turns `?raw` CSS into '') and checks 99 pairs per theme (text × 6 surfaces, hl × code backgrounds, on-accent, subtle badges, header, diff) ≥ 4.5:1 — own palette (R-11) — GitHub's Primer values.
- D-64 Router: `history.pushState({ key })` keeping `location.pathname + location.search` (mock switches live in the page query, route queries inside the hash), listens to `popstate` and `hashchange` (foreign hash entries get a key), `scrollRestoration = 'manual'`; `markRendered()` (RouteView layout effect) applies the remembered `scrollY`, retrying each frame for up to 2 s while async content grows — restore at first commit only (too short page clamps it).
- D-65 `useQuery`: fresh `requestId` per attempt; the cancel on last-unmount is deferred one microtask so StrictMode's mount/unmount/mount does not cancel; a `cancelled` rejection is never cached or shown (entry just goes stale); LRU eviction skips keys in use; `invalidate()` on window focus and on a finished job refetches mounted ref-keyed entries while showing the old data — no query library.
- D-66 M5 placeholders stay thin but real: RepoLayout (slug → repoId → detail → rev) is complete; the Code placeholder mounts the directory README through `MarkdownBody` (so the worker and language chunks are reachable and the markdown pipeline is checked in the browser; M6.5 swaps in ReadmeCard); RepoHeader's Fetch is offered for cloned repos only (imported needs the D-3 confirm, M6.4) and "Remove from shelf…" is disabled until M6; Import/Clone dialogs are working skeletons that M6.3 completes — empty placeholders (nothing to check in the browser, no hl chunks in `dist`).
- D-67 M5.13 browser check ran on a hidden `npm run dev` (PID recorded, killed with `taskkill /T /F`, port 1450 free afterwards) viewed in the desktop app's Browser pane, per the lead's instruction for subagents — the `reposhelf-mock` launch config is the lead's own preview.
- D-68 `navigate(to, { keepScroll })`: same-page query changes (`?q=` filter typing with `replace`, `?L=` line clicks) keep the scroll position instead of the router's scroll-to-top — a line click must not jump the page; Back must not step through keystrokes — a separate history-free URL API.
- D-69 After a mutation the library store AND the query cache are updated together (`state/repoCache.ts`: `applySummary` primes the lower-cased `repo_by_slug` key and evicts `repo_detail`; `forgetRepo` after Remove, which first navigates home) — RepoLayout reads its summary from the slug query, not the store — invalidating everything.
- D-70 Language colours are 12 own palette tokens (`--lang-0..11`, `--lang-other`, both themes) with fixed slots for common languages and a name hash otherwise, applied via `lang--N` classes (no inline colours); the selected-line background `--code-line-selected` joined the contrast test's code backgrounds — own look (R-11) — linguist colours.
- D-71 Non-UTF-8 entries are browsed via their lossy `path` (rs-core `tree::lookup` accepts it, WORKLOG M2); `pathRaw` only drives the "non-UTF-8 name" marker — TASKS M6.6 said "browse via `pathRaw`", but no command takes raw bytes — adding a raw-path IPC argument.
- D-72 File view: `blob_meta` first, then only what the kind allows (`blob_text` for displayable text, `blob_bytes` for images ≤ 5 MB, nothing for binary/LFS/submodule/symlink/> 5 MB); a `notFound` meta probes `tree_list` and redirects a directory to its tree route (replace) instead of matching message text; raw (`?plain=1`) is an in-app `<pre>`; the `?L=` anchor scroll runs two frames after mount and only on a fresh visit (`pendingScroll() === 0` at first render), so back/forward restore and the router's top-scroll win — scrolling in a layout effect (overridden by the parent's `markRendered`).
- D-73 Code viewer rows are fixed 20 px and never wrap; > 500 lines use `useWindowVirtualizer` with a re-measured scroll margin, and the horizontal width comes from the longest line in `ch` — exact `?L=` maths and sticky line numbers — wrapped lines with measured rows.
- D-74 Subdirectory latest-commit strip = `file_last_commit(dir)` + History link (rs-core `lastcommit::for_path` accepts directories); the root strip uses `commit_latest` and RepoLayout's exact `commit_count` key — GitHub-like per-folder header, shared cache — the ref's latest commit everywhere.
- D-75 The library store ignores `library-refreshed` events and `library_refresh` answers that belong to an earlier (reset) run (generation counter) — late events from a previous test's mock overwrote the next test's list (flaky `?empty`) — longer test sleeps.
- D-76 New command `app_open_dir { which: "data" | "archive" }` (48 commands; ARCH §5.1 row added) opens the app folder through the `Opener` (creating it first); anything else → `invalidInput`, never a path from the webview — M7.6 asks for "open via backend" and no command could open a non-repo folder — Copy path only / a path argument.
- D-77 Commit list URL = `?page=N` + pinned `?tip=` (+ `path`, `since`); without a path filter page N starts at walk position (N-1)·35, with one it starts at page N-1's returned `skip` (D-37), so `loadCommitsPage` walks pages 1..N-1 through a small module cache (keyed by the pinned tip) and reloads / Back work; the final page is an oid-keyed (stable) query — TASKS' `?tip=` + `?page=` kept as written — a `?skip=` in the URL (not human-readable, Newer cannot be derived).
- D-78 The commit row's expandable description is loaded on first expand from `commit_detail` (same stable key as the commit page) — `CommitSummary` has no body and widening the wire type would cost every page — an extra `body` field in `commits_page`.
- D-79 Branch ahead/behind is requested per fixed chunk of 20 rows once the chunk is on screen (sync `getBoundingClientRect` check at mount, then an IntersectionObserver), cancellable (`useQuery` cancelable, key = base + names); bars are scaled to the largest count loaded on the page; the compared branch is HEAD's branch (D-58) and gets no bar; a detached HEAD sends no request (src-tauri refuses it) and rows show a dash with a note (mock refuses too) — a growing visible-names key would cancel and restart on every scroll — one request for every branch.
- D-80 GitHub release notes: button only for `originHost == github.com`, confirm dialog (one request to api.github.com), the answer primes `releases_list`; `unsupported` hides the button for the session; the "loaded" date is this session's time (cards from the cache show a "GitHub notes" badge) — `Release` has no fetch date and S9 asks for one — a new wire field.
- D-81 Release links use full tag refs: tree `refs/tags/<tag>`, compare `commits/refs/tags/<tag>?since=refs/tags/<prev>` (banner shows short names) — a branch named like a tag must not win — TASKS' plain `commits/<tag>?since=<prev>`.
- D-82 The commit page collapses generated files even when an inline diff exists ("Load diff" then reveals it without a request); binary and > 1 MB files have no Load button; deferred stats are hidden (not "0 additions"); the mock now inlines generated files like rs-core — S6 lists generated among collapsed cards while rs-core inlines them — hiding nothing.
- D-83 File cards are virtualised past 40 cards through `WindowList` (window scroll, measured rows), which gained `scrollTo {index, seq}` (virtual: `scrollToIndex` with the sticky-header gap, re-measuring the list's page offset first — content above it such as the file list can grow — and on body resizes; plain: element offset); `?file=N` scrolls two frames after a fresh visit like D-72's `?L=`; the card header is sticky (so the card has no `overflow: hidden`) — one list component for all long lists — a separate virtualiser for cards.
- D-84 e2e-only OS seams in `src-tauri/src/e2e.rs` (module declared under `cfg(feature = "e2e")`, so shipped builds contain none of the env names; a source test keeps them out of every other file): `RS_E2E_PICK` (`;`-separated folder queue for the Rust-side folder dialog, empty → cancelled, save-as → cancelled), `RS_E2E_OPEN_LOG` (browser / Explorer opens appended to a file), `RS_E2E_OFFSCREEN=1` (main window created at −32000,−32000, unfocused) — the real app can be driven end to end without a native dialog or a window popping up on the user's screen — an external window-mover process (PM) / WebDriver minimize (does not reach WebView2).
